# Проверка контракта колодой

Контракт проверен картами К1–К10 из
[колоды P2](https://github.com/AIProgramIngeneering2026/Zadania/blob/main/tasks/p2_poker/README.md#колода).
Источники контракта:

- [`api/openapi.yaml`](api/openapi.yaml) - HTTP API, коды ответов, единый формат ошибок;
- [`architecture.md`](architecture.md) - компоненты и диаграмма состояний Job;
- [`tool-contract.md`](tool-contract.md) - контракт `ITool` / `ToolResult`, OCR Tool и Statistics Tool;
- [`adr/`](adr/) - архитектурные решения.

## Карты К1–К10

| Карта | Ответ контракта |
|---|---|
| К1 Двойной клик | `Idempotency-Key` обязателен. Одновременные запросы с одним ключом создают ровно один Job: первый получает `202`, остальные `200` с тем же `id`; при другом файле или параметрах `409 idempotency_conflict` - [`openapi.yaml`](api/openapi.yaml), `POST /jobs`, ответы `202`, `200`, `409` |
| К2 Ответ потерялся | Клиент повторяет тот же запрос с тем же ключом и получает `200` с прежним `id` и текущим состоянием, в том числе после завершения Job. После `503` клиент тоже повторяет запрос с тем же ключом - [`openapi.yaml`](api/openapi.yaml), `POST /jobs` (описание), `components.responses.ServiceUnavailable` |
| К3 Неизвестная операция | Клиент не выбирает операцию: `POST /jobs` всегда запускает OCR и подсчёт статистики. Неизвестное поле тела или `parameters` и значение `language` вне `ru`/`en` дают `422 invalid_parameters` с указанием поля; Job не создаётся - [`openapi.yaml`](api/openapi.yaml), `CreateJobRequest`, `ProcessingParameters` (`additionalProperties: false`), ответ `422` |
| К4 Кривые параметры | Неверное значение или отсутствующее поле: `422 invalid_parameters`, `errors` содержит ключ поля (`file`, `parameters.language`, `Idempotency-Key`). Неразбираемый JSON или multipart: `400 invalid_request` с `errors.parameters` или `errors.body` - [`openapi.yaml`](api/openapi.yaml), `ProblemDetails.errors`, `components.responses.BadRequest`, ответ `422` |
| К5 Воскрешение | Запрещено: `done` и `failed` конечные, любой переход из них отклоняется доменной ошибкой, итог не перезаписывается - [`architecture.md`](architecture.md#запрещённые-переходы-и-реакция-системы). Повтор `POST` с прежним ключом возвращает тот же Job без перезапуска; новая обработка требует нового ключа и создаёт новый Job, прежний результат сохраняется - [`openapi.yaml`](api/openapi.yaml), `POST /jobs` |
| К6 Отмена | Не поддерживается, сознательно: Job доходит до `done` или `failed`, клиент может не читать результат - [ADR-0003](adr/0003-no-job-cancellation.md); операции отмены в API нет - [`openapi.yaml`](api/openapi.yaml), `info.description` |
| К7 Огромный вход | Тело больше лимита (по умолчанию 20 МиБ, настраивается) отклоняется `413 payload_too_large` до сохранения файла и создания Job; OCR не вызывается - [ADR-0004](adr/0004-input-size-limit.md), ответ `413` в [`openapi.yaml`](api/openapi.yaml). Долгое распознавание документа в пределах лимита ограничено тайм-аутом OCR и завершается `failed` с `ocr_timeout` - [`openapi.yaml`](api/openapi.yaml), `JobFailure` |
| К8 Чужой или несуществующий id | Несуществующий корректный UUID: `404 job_not_found`; некорректный: `400 invalid_request` с `errors.id` - [`openapi.yaml`](api/openapi.yaml), `GET /jobs/{id}`. «Чужой» id неприменим: в первой версии нет аутентификации и понятия владельца задания, `id` - случайный UUID, знание `id` даёт доступ к Job - [`openapi.yaml`](api/openapi.yaml), `info.description` |
| К9 Перезапуск сервера | Задания в `created` хранятся в БД и подхватываются Dispatcher после старта. Задания в `running` при старте переводятся в `failed` с кодом `processing_interrupted`; автоматического продолжения нет, для новой обработки нужен новый ключ - [ADR-0001](adr/0001-background-job-processing.md#восстановление-после-перезапуска), `JobFailure` в [`openapi.yaml`](api/openapi.yaml) |
| К10 Внешний сервис | Молчание дольше тайм-аута: один повтор, после второго тайм-аута `failed` с `ocr_timeout`. Мусор или переименованное поле: адаптер OCR не принимает ответ, Job переходит в `failed` с `ocr_invalid_response` без повтора. Клиент видит `GET /jobs/{id}` → `200`, `status: failed`, причина в `error` - [`openapi.yaml`](api/openapi.yaml), `JobFailure`; [`architecture.md`](architecture.md#ответственность-и-границы-компонентов), адаптер OCR |

## Что предложил ИИ

Модель: Claude Opus 5.5. На вход переданы `openapi.yaml`, `tool-contract.md`, `architecture.md`,
ADR-0001, ADR-0002 и колода К1–К10.

**Промпт**

> Ты атакующий в упражнении «покер контрактов». Ниже контракт сервиса конвейера обработки документов:
> OpenAPI-спецификация, контракт Tool, архитектура с диаграммой состояний Job и ADR. Ниже - колода карт К1–К10
> с ситуациями, которые уже проверены. Найди ещё 3 ситуации, которые не повторяют карты колоды и на которые
> контракт не отвечает или отвечает противоречиво. Для каждой ситуации опиши: условия, что сломается,
> какое место контракта не даёт ответа и что увидит клиент. Ссылайся на конкретные операции, схемы и разделы.
>
> [содержимое openapi.yaml, tool-contract.md, architecture.md, ADR-001, ADR-002]
>
> [таблица колоды К1–К10]

| Находка ИИ | Решение |
|---|---|
| **Повреждённый или зашифрованный PDF.** Файл начинается с `%PDF-` и проходит проверку сигнатуры, но защищён паролем или повреждён. OCR отклоняет документ, а в `JobFailure` нет кода для этого случая: сбой попадает в `ocr_unavailable` (503). Клиент считает, что сервис временно недоступен, и повторяет загрузку того же файла с новым ключом. | **Приняли.** `unreadable_document` добавлен в `JobFailure` и [ошибки OCR Tool](tool-contract.md#ошибки). Job завершается с `failed`, повтор не выполняется. Глубокий разбор PDF при приёме не вводим. |
| **Частый опрос состояния.** Клиенты опрашивают `GET /jobs/{id}` в цикле без пауз. При SQLite запись Dispatcher конкурирует с чтениями, переходы в `running` и `done` задерживаются. Контракт не говорит клиенту, как часто опрашивать. | **Приняли частично.** В [`openapi.yaml`](api/openapi.yaml) добавлен `Retry-After` с рекомендуемой паузой, по умолчанию 2 секунды, для `POST → 202` и `GET → 200` в `created`/`running`. Это рекомендация клиенту. Принудительное ограничение частоты запросов в первой версии не вводим из-за учебной нагрузки. |
| **Документ на тысячи страниц.** Небольшой по размеру PDF с тысячами пустых страниц проходит лимит размера. Распознавание занимает слот обработки до тайм-аута на каждой из двух попыток, очередь заданий растёт. | **Не приняли.** Две попытки ограничивают время ожидания OCR. Они не ограничивают очередь, подсчёт статистики и сохранение результата. Длина очереди сознательно не ограничена в первой версии; рост ожидания требует пересмотра [ADR-0001](adr/0001-background-job-processing.md#последствия-решения). Лимит страниц требует разбора PDF при приёме ([ADR-0004](adr/0004-input-size-limit.md), альтернатива 2). |

## Найденные проблемы и решения

| # | Проблема | Источник | Решение |
|---|---|---|---|
| 1 | Не определён лимит размера входа | К7 | Лимит 20 МиБ и отказ до сохранения PDF описаны в [ADR-0004](adr/0004-input-size-limit.md), ответ `413 payload_too_large` добавлен в [`openapi.yaml`](api/openapi.yaml). |
| 2 | Не обоснован отказ от отмены | К6 | Решение и альтернативы описаны в [ADR-0003](adr/0003-no-job-cancellation.md). |
| 3 | Код прерванного Job отсутствовал в API | К9 | `processing_interrupted` добавлен в `ProblemDetails.code` и `JobFailure.code`; пример ответа есть в [`openapi.yaml`](api/openapi.yaml). |
| 4 | Коды OCR Tool отличались от API | К10 | Коды согласованы в [контракте Tool](tool-contract.md#ошибки) и `JobFailure`. |
| 5 | Два владельца повтора OCR | К10 | В [архитектуре](architecture.md#состояния-job) и [контракте Tool](tool-contract.md#повторные-попытки) повтор выполняет только Dispatcher. |
| 6 | Имена и ссылки ADR расходились | Проверка | Файлы и ссылки приведены к формату `0001-…`–`0004-…`. |
| 7 | Счётчики Tool и API имели разные типы | Проверка | `long` в [Statistics Tool](tool-contract.md#выходные-данные-1) соответствует `int64` в API. |
| 8 | Не описан нечитаемый PDF | ИИ | `unreadable_document` добавлен в контракт Tool и API, пример ответа есть в `openapi.yaml`. |
| 9 | Не указана частота опроса | ИИ | Заголовок `Retry-After` описан в API; принудительного ограничения частоты нет. |
