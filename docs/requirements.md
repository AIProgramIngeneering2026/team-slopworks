# Требования к конвейеру обработки документов

## Сценарии

### Повторная отправка запроса на обработку

**Цель** — получить идентификатор задания при повторе запроса, если ответ на первую отправку потерялся.

**Участник** — пользователь сервиса.

**Поток**

1. Пользователь отправляет документ и параметры обработки с ключом идемпотентности.
2. Сервис принимает запрос и создаёт задание. Пользователь не получает ответ, например из-за обрыва соединения.
3. Пользователь повторяет запрос с тем же файлом, параметрами и ключом.
4. Сервис возвращает идентификатор уже созданного задания. Пользователь может по нему проверить состояние обработки.

**Критерии приёмки**

- **Дано** — для ключа уже создано задание. **Когда** — пользователь повторяет запрос с теми же байтами файла и теми же параметрами обработки. **Тогда** — сервис возвращает исходный идентификатор, а в истории остаётся одно задание для этого ключа.
- **Дано** — ключ ещё не использован. **Когда** — два одинаковых запроса с этим ключом поступают одновременно. **Тогда** — оба ответа содержат один идентификатор и создаётся ровно одно задание.

### Загрузка файла неподдерживаемого формата (ошибочный сценарий)

**Цель** — сразу узнать, почему файл нельзя отправить на обработку.

**Участник** — пользователь сервиса.

**Поток**

1. Пользователь отправляет файл на извлечение текста из PDF.
2. Сервис проверяет содержимое файла перед созданием задания и обнаруживает, что это ZIP-архив.
3. Сервис возвращает ошибку в едином формате API и указывает, что для этой операции нужен PDF.

**Критерии приёмки**

- **Дано** — пользователь отправляет ZIP-архив на извлечение текста из PDF. **Когда** — сервис проверяет файл. **Тогда** — ответ содержит причину отказа, задание не создаётся, OCR не вызывается.
- **Дано** — ZIP-архив переименован в `scan.pdf` и передан с типом `application/pdf`. **Когда** — сервис проверяет файл. **Тогда** — он возвращает ту же ошибку и задание не создаётся.

### Внешний OCR не отвечает (ошибочный сценарий)

**Цель** — узнать, что извлечение текста завершилось ошибкой, если внешний сервис распознавания недоступен.

**Участник** — пользователь сервиса. Внешняя система — OCR-сервис.

**Поток**

1. Пользователь отправляет сканированный PDF на извлечение текста и получает идентификатор задания.
2. Сервис начинает обработку и отправляет документ в OCR. По истечении тайм-аута сервис повторяет вызов один раз.
3. Повторный вызов тоже завершается по тайм-ауту. Сервис сохраняет причину ошибки и переводит задание в состояние «отклонён».
4. Пользователь запрашивает состояние задания по идентификатору и видит причину ошибки.

**Критерий приёмки**

- **Дано** — задание принято, а тестовый OCR-сервис не отвечает на оба вызова в пределах настроенного тайм-аута. **Когда** — сервис обрабатывает задание. **Тогда** — после двух попыток сервис прекращает обращения к OCR, сохраняет состояние «отклонён» и при запросе состояния сообщает, что OCR не ответил. Результат извлечения текста отсутствует.

## Что предложил ИИ

**Промпт**

> Основной сценарий конвейера обработки документов: пользователь загружает сканированный PDF и получает идентификатор задания. Сервис отправляет документ во внешний OCR, сохраняет извлечённый текст, после чего пользователь может запросить результат по идентификатору. Найди три разных способа сломать этот сценарий помимо явного тайм-аута OCR и загрузки файла с заведомо неподдерживаемым расширением. Для каждого опиши условия сбоя и наблюдаемый эффект.

| Предложение ИИ | Решение и обоснование |
| --- | --- |
| Пользователь повторяет запрос, пока первый ещё обрабатывается. Оба запроса могут создать свои задания, если проверка ключа и создание задания выполняются раздельно. | **Приняли.** Добавили критерий для одновременных запросов. Одно задание для одинаковых запросов с одним ключом исключает повторную обработку и даёт пользователю один идентификатор. |
| ZIP-архив выдают за PDF, меняя расширение и объявленный тип файла. Проверка только этих признаков пропустит архив на этап распознавания. | **Приняли.** Добавили критерий для замаскированного архива. Проверка содержимого до создания задания позволяет сразу объяснить отказ и избежать лишнего обращения к OCR. |
| OCR возвращает ответ в ожидаемом формате, но пропускает страницу. Конвейер может отметить задание успешным и выдать неполный текст. | **Не приняли в первую версию.** Чтобы обнаружить пропущенную страницу, сервису нужны результаты OCR с номерами страниц. Для первой версии достаточно результата в виде общего текста документа. |
