# ADR-004: Ограничение размера входного файла

- **Дата:** 15.11.2026
- **Статус:** Accepted

## Контекст и ограничения

`POST /jobs` принимает PDF в `multipart/form-data`. Принятый файл сохраняется в локальной файловой системе, затем передаётся во внешний OCR. Файл в сотни раз больше обычного занимает диск, память при разборе запроса и время OCR, хотя пользы от его обработки в первой версии нет.

Проверка содержимого выполняется до создания Job. Отказ должен приходить в едином формате ошибок API, задание при отказе не создаётся.

## Решение

1. Размер тела запроса `POST /jobs` ограничен настройкой приложения. Значение по умолчанию 20 МиБ.
2. Превышение лимита отклоняется до сохранения файла, до проверки содержимого и до создания Job. OCR не вызывается.
3. Ответ: `413` в формате ProblemDetails с `code: payload_too_large` и `errors.file`, где указан допустимый размер.
4. Лимит проверяется на уровне сервера (ограничение размера тела запроса), а не после чтения файла целиком.

## Рассмотренные альтернативы

### 1. Без лимита

Недостатки:

- Один запрос может исчерпать диск или память.
- Большой файл гарантированно упирается в тайм-аут OCR и всё равно завершается `failed`, но только после сохранения и двух вызовов OCR.

Вариант не выбран.

### 2. Лимит по числу страниц

Точнее отражает нагрузку на OCR, чем размер в байтах.

Недостатки:

- Требует разбора PDF при приёме запроса.
- Не защищает от большого файла с малым числом страниц.

Вариант не выбран для первой версии.

## Цена решения

- Документы больше лимита нельзя обработать, клиенту нужно разделить файл.
- Значение 20 МиБ выбрано без замеров и может оказаться неподходящим для реальных сканов.
- Документ с большим числом страниц в пределах лимита по-прежнему ограничивается только тайм-аутом OCR.

## Условия пересмотра решения

- Пользователям регулярно нужны документы больше лимита.
- Замеры покажут, что OCR не справляется с файлами в пределах лимита.
- Появится разбор PDF при приёме, и станет возможен лимит по страницам.
